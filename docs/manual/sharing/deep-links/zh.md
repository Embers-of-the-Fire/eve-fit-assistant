# 应用内链接

应用内容中出现的链接——手册页面、公告及类似文本——在任何位置都有一致的打开方式。

**内部链接**使用 `efa://` 协议。协议后的部分是应用内页面路径，例如 `efa://manual/sharing` 会打开本手册章节。点击后该页面会被推入导航栈，效果与手动导航相同。

**外部链接**——`https://`、`mailto:` 等其他协议——会在设备的外部浏览器或对应应用中打开。

内容作者还可以使用相对当前页面的链接（包括用 `..` 返回上一级），它们会解析到相同的应用内页面。

如果内部链接指向不存在的页面，点击会被忽略并记录到应用日志中，不会造成任何错误。

注意：`efa://` 链接仅用于应用**内部**导航，并非网页链接。如需从应用外部通过链接打开配置，请参见下方的配置链接。

# 配置链接

导出对话框中的**复制链接**操作会生成如下形式的分享链接：

```text
https://share.platform.efa-tech.dev/fit/raw?payload=EFA2:...
```

链接中的负载以应用原生格式携带完整配置（与 EFA 原生文本导出内容相同），直接编码在 URL 中，不会上传到任何服务器。过大的配置无法以链接形式分享，请改用文本导出。

打开配置链接时会出现一个选择页面，接收者可以选择打开方式：

- **在应用中打开**——启动已安装的应用并导入配置（作为副本导入，不会修改现有配置）。如果没有应用响应，页面会提供下载入口。
- **在网页版中打开**——将配置导入到 `app.efa-tech.dev` 的网页应用中。
- **在每日构建中打开**——同上，但使用预览构建。

每种方式都可以勾选记住；下次打开链接时会自动重定向，并提供取消和重置入口。

平台支持情况：

- **Android**——所有链接域名均支持已验证的 App Links，并支持 `efa://` 协议。验证完成后打开链接会直接进入应用。
- **Windows**——安装 MSI 后会注册 `efa://` 协议。
- **Linux**——尽力而为：AppImage 的桌面条目声明了 `x-scheme-handler/efa`，但只有当你的 AppImage 集成工具（如 appimaged 或 Gear Lever）安装桌面条目时才会生效。
- **网页版**——在任一网页版域名打开配置链接都会导入配置，并从地址栏中清除负载。

已损坏或并非配置链接的链接会在应用内显示错误，或在分享站点显示“链接不存在”页面——两种情况下都不会导入任何数据。
